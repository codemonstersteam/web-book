Я строю разработку как **инженерную дисциплину**, а не как ремесло. Опираюсь на научный фундамент — работы Вирта, Дейкстры, Миллса: программа должна быть [структурирована](https://codemonsters.team/blog/2025/12/12/structured-programming-essential/) и [модульна](https://codemonsters.team/blog/2025/12/15/program-modules/) по построению, а её [правильность — выводима и доказуема](https://codemonsters.team/blog/2025/12/30/program-correctness/), а не «проверена на глаз».

Мой главный принцип — **рациональная экономия на каждом этапе**. Писать **меньше кода** и **меньше тестов**: ровно столько, сколько нужно, и ни строкой больше. Каждый артефакт нанимается на конкретную работу по JTBD — [README как продукт](https://codemonsters.team/blog/2026/04/07/documentation-as-product-jtbd/), [сколько компонентных тестов нужно сервису — логический вывод](https://codemonsters.team/blog/2026/04/25/testing-mythology-component-tests/), [корректность системы, собранная из корректности сервисов](https://codemonsters.team/blog/2026/05/12/composition-of-correctness/).

ИИ для меня — не серебряная пуля, а инструмент, который надо применять рационально. Дорогая модель проектирует дисциплину — дешёвая исполняет. Нельзя позволять LLM **умножать безграмотные решения**: задача инженера — чтобы машина усиливала правильное, а не тиражировала мусор.

## Над чем работаю сейчас {#now}

Весь этот опыт и знания я воплощаю в **агентах**.

**Харнес** [`rationaldev-ai-sdlc-skills-front`](https://github.com/codemonstersteam/rationaldev-ai-sdlc-skills-front) — фундамент. Подключаемый мультиагентный SDLC-конвейер, где мои практики разложены по ролям-агентам: от бизнес-требования до мержа в прод — один конвейер, а человек принимает решения на гейтах.

Чтобы такой конвейер работал в полную силу, нужен **контроль качества работы агентов**. Над этим — два инструмента:

- [`pinout`](https://github.com/codemonstersteam/pinout) — проверяет совместимость сервисов по их OpenAPI/AsyncAPI-спецификациям на pre-merge: контракты сходятся до прода, а не падают в рантайме;
- [`rra`](https://github.com/codemonstersteam/rra) (Rational Repository Auditor) — объективная CI-метрика дисциплины: отделён ли I/O от бизнес-логики и понятна ли документация по JTBD.

??? info "В чём научность `rra` — раскрыть"
    RRA не «линтер стиля» и не «покрытие тестами». Он измеряет дисциплину по двум критериям, у каждого — своя научная опора.

    **Код — I/O отделён от бизнес-логики (корректность по построению):**

    - структурное программирование (Вирт, Дейкстра): «программа = дерево модулей», у каждого одна функция;
    - «качество достигается проектированием, а не тестированием» (традиция Миллса/Лингера, cleanroom): логика чиста, зависимости — автономные I/O-объекты, возврат `Result<T,E>`;
    - метод: статика по AST и графу импортов (~70–80% бесплатно) → семантика LLM с обязательной цитатой строки → сверка с проектным `contracts-graph.md`. Моки в юнит-тестах = сигнал протёкших зависимостей.

    **Документация — понятность по JTBD (слои L1–L6):**

    - **L1 читаемость** — формулы с 80-летней валидацией: Flesch (1948), Flesch-Kincaid (1975), Gunning Fog, SMOG, Coleman-Liau; российская школа — Микк, Оборнева, Солнышкина (формула ФКМОД);
    - **L2–L3 ясность** — Cognitive Load Theory (Sweller, 1988) и «эффект смысловых ножниц» Дридзе (1984) → согласованная терминология; инструменты Vale, markdownlint;
    - **L4–L5 пригодность** — Jobs-to-be-Done: документацию нанимают [четыре потребителя](https://codemonsters.team/blog/2026/04/07/documentation-as-product-jtbd/); статический чеклист + LLM-симуляция ролей. Четыре независимых score, **не усредняем** («документация для всех = ни для кого»).

    **Сквозной принцип:** отправная точка — DORA (2022, качественная дока = +25% производительности), но её субъективные шкалы Ликерта RRA заменяет объективной метрикой на каждый PR. LLM подключается рационально: «дешёвая модель применяет, дорогая думает» — ИИ только на верхних слоях и только если нижние (статика, линтеры) пройдены.

    Полностью — в [`rra/CONCEPT.md`](https://github.com/codemonstersteam/rra/blob/main/CONCEPT.md) и [`concept-docs-readability.md`](https://github.com/codemonstersteam/rra/blob/main/concept-docs-readability.md).

Вместе это замыкает контур: **агенты пишут — инструменты держат планку**.
